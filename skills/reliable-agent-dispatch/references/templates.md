# 派单、交付与接续模板

复用现有记录即可；模板字段按本题删减，不要求把每项填成长文。

## 派单

```text
任务：用户能看到的结果
证据：反馈原话、获准输入或直接日志
负责人：唯一执行者
车道经理：唯一派单、接住最终或阻塞回执并恢复原线程的人；单一小任务无需经理
基线：代码目录、分支或版本、已有改动
范围：允许修改的文件或模块；独立工作树默认允许同文件并改，明确列出的热点除外
禁止：本题不得触达的资产和操作
执行：每一步在哪台获准机器、哪个目录运行
验收：具体动作、预期结果、可用验证入口
交付：结果及证据保存位置；如何通知直属经理
```

## 交付

```text
任务：稳定名称或编号
证据层级：源码候选 / 构建 / 实际操作 / 集成 / 发布 / 用户验收（分别报告，不作为阶段派单）
结果：完成什么，未完成什么
身份：分支、提交、运行程序及输入输出的可核对身份
证据：本次差异、相关验证、必要保存与重新打开结果
下一步：谁在什么条件下做哪个具体动作
清理：已清理项；尚有使用者时写清最后使用者和结束即清条件
```

## 交付消费记录

```text
结论：最终或阻塞回执的结果与证据是否齐备，不逐步核收
接续：已调用原线程恢复工具及回执 / 依赖提供者与到位触发 / 已转交责任
负责人：原负责人或明确继任者
完成条件：剩余哪一步满足后才可结项
状态：处理中 / 等你定 / 待发版 / 已完成；确认接住不等于用户目标完成
```

同题各阶段由原执行者直接继续，不交回经理重新派单。只有工具证实无法恢复才登记继任；经理退出时转交协调责任，保留执行者和原记录。

## 类治理与依赖提议

```text
原问题：止血线负责人、实际用户链结果与剩余步骤
类别：已有类别或新类试点；同类复用的治理主线
授权范围：允许盘点和修改的入口；未获授权时仅提建议
盘点：已迁移 / 现有能力足够及依据 / 暂不做及原因触发
未结：未查、待迁、待验及当前依赖，保持明确负责人，不另设反馈状态
守护：静态规则、扫描范围、存量允许集合、登记入口与实际耗时
成熟做法：候选、官方来源、版本许可、替代逻辑、体积兼容代价与推荐
终点：范围盘点闭合且棘轮已登记；原缺陷、类别和发布分别结算
```

细节按任务读 [bug-by-class.md](bug-by-class.md) 或 [mature-libraries.md](mature-libraries.md)，不要求每个单点修复填写整张表。

## 用户状态

```text
一句完整的话说明用户可见结果和当前缺口。

问题 / 当前结果 / 还差什么
导出后缺少一列 / 源码修复且相关测试通过 / 指定平台的真实导出与保存回读

需要用户决定：问题、推荐与具体做法、不选推荐的代价、实际呈现及答复。
超时：已采用约定的普通决定呈现后 3 分钟按推荐；硬边界无明确授权不自动许可。
证据：内部目录、提交、进程和详细日志。
```
