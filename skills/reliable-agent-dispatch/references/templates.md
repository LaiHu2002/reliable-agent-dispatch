# 派单、交付与接续模板

复用现有记录即可；模板字段按本题删减，不要求把每项填成长文。

## 派单

```text
任务：用户能看到的结果
证据：反馈原话、获准输入或直接日志
负责人：唯一执行者
直属经理：唯一派单、消费交付并接续的人；小任务可由主调度兼任
基线：代码目录、分支或版本、已有改动
写权：允许修改的文件或模块
禁止：本题不得触达的资产和操作
执行：每一步在哪台获准机器、哪个目录运行
验收：具体动作、预期结果、可用验证入口
交付：结果及证据保存位置；如何通知直属经理
```

## 交付

```text
任务：稳定名称或编号
阶段：源码候选 / 构建 / 实际操作 / 集成 / 发布 / 用户验收
结果：完成什么，未完成什么
身份：分支、提交、运行程序及输入输出的可核对身份
证据：本次差异、相关验证、必要保存与重新打开结果
下一步：谁在什么条件下做哪个具体动作
清理：已清理项；尚有使用者时写清最后使用者和结束即清条件
```

## 交付消费记录

```text
核对：差异及证据支持什么结论
接续：已调用恢复工具及回执 / 明确排队 / 外部缺口
负责人：原负责人或明确继任者
完成条件：剩余哪一步满足后才可结项
确认：该交付已消费；整个任务是否完成单独记录
```

同题各阶段沿原任务接续。换负责人或转组时记录旧负责人停止新派工、检查点及继任接手，不关闭原任务另开一条来消除未完成责任。

## 类治理与依赖提议

```text
原问题：止血线负责人、实际用户链结果与剩余步骤
类别：已有类别或新类试点；同类复用的治理主线
授权范围：允许盘点和修改的入口；未获授权时仅提建议
盘点：已迁移 / 现有能力足够及依据 / 暂不做及原因触发
未结：未查、待迁、待验及排队，保持明确负责人
守护：静态规则、扫描范围、存量允许集合、登记入口与实际耗时
成熟做法：候选、官方来源、版本许可、替代逻辑、体积兼容代价与推荐
终点：范围盘点闭合且棘轮已登记；原缺陷、类别和发布分别结算
```

细节按任务读 [bug-by-class.md](bug-by-class.md) 或 [mature-libraries.md](mature-libraries.md)，不要求每个单点修复填写整张表。

## 用户状态

```text
一句完整的话说明用户可见结果和当前缺口。

问题 / 当前结果 / 还差什么
导出后缺少一列 / 源码修复且相关测试通过 / 指定平台的真实导出与保存回读

需要用户决定：只列真正影响结果、无法由现有证据确定的事项。
证据：内部目录、提交、进程和详细日志。
```
