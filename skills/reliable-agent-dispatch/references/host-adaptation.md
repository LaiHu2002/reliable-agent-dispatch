# 宿主工具适配与验证

本技能描述行为；实际宿主提供代理工具、文件系统、授权和执行能力。按当前工具合同填写映射，不能把一个产品的工具名称当成其他产品也具备的接口。

| 操作 | 必须核实的语义 |
| --- | --- |
| 启动 | 是否真正启动执行，返回什么可查询身份 |
| 通知 | 是否仅排入消息，能否唤醒闲置执行者 |
| 恢复 | 是否启动新一轮，保留哪些原上下文与目录 |
| 列状态 | 状态有多新，结束、等待和正在运行怎样区分 |
| 等待 | 是否有界等待，能否接收用户新消息和其他交付 |
| 持久交付 | 是否先保存后发送，失败如何可见，谁确认 |
| 分层归属 | 同一任务的执行者与直属经理如何分别记录，谁唯一消费交付 |
| 资源查询 | 能否只查获准机器，采样是否可信，如何计入已分配未启动的任务 |
| 主调度恢复 | 对话停止、应用重启或机器离线后，谁触发继续 |

例如某些环境把“通知”和“恢复”做成不同工具。应依据当前说明使用，不能仅因消息发送成功就报告已经启动。没有某项工具时保留未知或写明缺口，不编造接口。

## 一次小规模行为检查

在获准的临时目录，用两个无害、互不写同一文件的任务验证适配：一个执行者先交付，另一个继续工作。直接调度时由主调度接收；使用经理制时由一位经理带两位执行者，检查交付能否到经理、经理是否核结果并实际续派，主调度与用户沟通期间接续能否继续。

再核巡检能否把未接事件送给准确经理；若授权恢复，确认工具确实启动下一轮。重试不得造成同任务双执行或两位经理同时确认。模型服务容量失败、代理名额不足和机器任务失败分别保留原始原因，恢复前核旧进程是否仍在，不能用别的入口绕过限制。

再模拟一次交接：让继任调度只读取任务记录和实际工具状态，判断哪些已完成、哪些需要恢复。不要为测试关闭他人会话、终止未知进程或制造生产故障。

记录实际结果与失败。此检查仅验证当前宿主和这一次输入，不构成长时间稳定性、离线唤醒或跨平台兼容证明。跨宿主的效果需要分别验证。

## 能力与指令分界

- 技能可以要求先落盘交付；写入成功、并发控制和通知重试依赖实际实现。
- 技能可以要求及时接续；停止会话后的唤醒依赖宿主机制。
- 技能可以要求按机器分配；实际负载探测、远程执行和桌面隔离依赖已有工具。
- 技能可以要求证据分级；证据本身仍须来自实际操作。

经理容量和模型分工是当前批次配置，实际工具名额和机器负载另核。不要自动改全局设置、迁移活跃队列、增加后台服务或建立定时任务；需要这些动作时按用户授权和宿主正式入口处理。
