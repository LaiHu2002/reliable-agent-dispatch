# 协调结构：经理是按需调用的公共设施

本文件执行[第二版](../../../docs/coordination-structure.md)。一个独立问题由同一执行者做到底，经理负责接住、恢复和转达决定，不按业务带组、不逐步核收。

## 角色与责任

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| 执行者 | 定位、实现、测试、必要构建、真实验收、保存回读、清理、候选登记；自己查机器和等构建 | 不把阶段边界交给经理重新派人 |
| 主调度 | 用户唯一联系人；转达原话、反馈、决定与授权；及时呈现待决定事项并写回答复 | 不派执行者、不接车道、不读执行过程 |
| 车道经理 | 启动独立问题的执行者；停住或依赖到位恢复原线程；转达待决定事项；拉起集成和发版 | 不对接用户、不按业务分组、不逐步核收 |
| 公共设施 | 机器脚本、集成和发版执行者、高风险独立审查、界面协作 | 不设常驻资源代理，不另带执行组 |
| 巡检 | 低成本查漏接、依赖到位未唤醒、责任挂在不活动经理名下的问题，报主调度 | 不派业务、不规划、不接管实现 |

接不过来才增加协调者，不按固定未结数量配经理。代理名额、机器负载和协调成本分别判断；模型按任务及用户分工选择，不固定品牌或版本。

## 原线程做到终点

首次派单覆盖最终用户动作、必要平台、保存后新进程回读、清理和回执。换阶段、机器或等待时保留原线程，不交一次阶段结果就结束责任。

继续时调用真正能恢复原线程的工具，通知不能冒充启动。只有工具证实无法恢复才登记继任，先核在途进程与现场，继任只读最后最小回执和开工必需材料。

高风险审查和界面协作不接管端到端责任。普通候选由实现者自审和测试，高风险按项目规范独立审查，不为每次阶段进展另开审查。

经理用能被交付唤醒的长超时等待，不重读过程。只向主调度发待用户决定、关键路径卡住超过 15 分钟、每日晚报；卡点必须修工具重试、换获准路径或经主调度问用户。

## 四状态与决定

每条反馈只有**处理中、等你定、待发版、已完成**，与技能正文共用记录。等机器或构建仍是处理中，依赖、提供者与恢复条件是字段，不另设排队或等外部状态。

待决定事项写清问题、推荐、具体做法和不选推荐的代价，主调度实际呈现后才起算。在用户或项目已采用约定且宿主允许时，普通决定 3 分钟无回复按推荐并记录；未呈现不能起算。发版、云端部署、客户和公开数据写入、永久删除、凭据及权限变化没有明确授权永不自动许可。

缺证据先找原件，仍缺则登记请求及可直接发送的文案，用现有材料完成可做部分，注明原案未覆盖。证据到位由原执行者重开补验；待发版须有候选身份和验证层级，已完成须写结果，公开回读通过才能记为已发布修复。

## 资源用现成脚本

执行者查询获准机器的实时负载，登记运行中和已分配未启动的占用，避免凭同一空闲快照重复分配。不设资源经理，不把一次内存或磁盘实测抄成普遍开场门槛；限制来自真实用户边界或项目规范。

| 约束 | 核什么 |
| --- | --- |
| 代理名额 | 当前工具实际接纳及协调者、巡检占用 |
| 机器负载 | 当前内存压力、处理能力、重任务和已知同类峰值 |
| 磁盘与工具 | 本线输出位置、真实余量、工具链和运行环境 |
| 共享对象 | 少数明确列出的热点、生成产物或现场归属 |
| 桌面焦点 | 哪一步要前台、用户是否占用、隔离是否已验证 |

只暂停受限动作，其他独立工作继续。使用独占构建目录，不借其他线输出；新机器须有登记、授权和可执行连接，不扫描未登记设备或改认证。

## 乐观合并，少数热点才串行

各线在独立工作树直接改，同一文件可以并行；先合者先进，后合者在最新基线上变基并保留已合入内容。不整文件格式化、不大段搬动、不批量重命名。

确有必要才列热点单写清单，默认空。共享生成产物可由最终集成者统一生成，不把整个文件或集成阶段都串行化。

集成、发版各由一个执行者干到底，复用证据并核真实组合身份。发布授权后核候选并冻结范围；新反馈归后续版本，用户加项或本版回归才重新冻结。范围、最终产物、公开回读和清理由原发布执行者完成，集成许可不等于公开发布许可。

## 接续、转交与巡检

执行者保存最终或阻塞回执再通知，只写结果、证据与剩余动作。经理落实原线程恢复、依赖接续或责任转交后确认，不逐步审查执行日志。

经理挂起或退出时，当轮转交未结责任，保留原执行者、记录和句柄。巡检只核记录与工具是否一致、是否漏接、依赖到位未唤醒；不能靠清空队列证明用户结果完成。

每天汇总每个问题的线程数、中途来回次数、管理类 token 占比。原实践目标为 1–2 个线程、不超过 3 次、约 30%，是该环境目标，不是保证。

## 借工作方法先对照前提

先列上下文长度、缓存与计费、任务长度及人机分工，逐条对照，再选小批车道试跑一两天。比较线程数、交付来回、管理占比和完成的用户问题，不能只看单次请求快慢；变好推广、变差撤回，出处有名不能代替验证。

执行者间直接协作仍是第二版主文的小范围试跑，不把尚无结果的做法写成已验证规则。
