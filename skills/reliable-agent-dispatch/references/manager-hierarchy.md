# 按任务设经理，按负载分配资源

当主调度接收交付的速度赶不上执行者产出时，把日常接续交给经理。增加巡检只能更早发现积压，不能替代处理交付的负责人。单一任务无需建管理层。

## 分组与容量

按共同根因、写集、依赖和验收结果分组，不预设经理人数或业务部门。主调度掌握原始目标、各组范围和优先级；经理核本组意图，直接派执行者、审查交付并追到约定结果。常规接续不再等主调度逐条批准。

给每位经理设一个当前可管理的未结任务预算，排队、待验证、待集成和外部等待都占管理容量；阶段交付不自动释放责任。原实践从五六条的注意力容量假设，试到每位经理最多十条未结任务。使用者应根据交付积压、接续延迟和上下文成本调整，不以填满预算为目标。

先用“主调度 → 经理 → 执行者”。确有积压先拆组或补资源，有独立子目标再考虑增加层级；任务结束收回空闲管理职责。工具的整棵代理树共享名额，新增经理也有成本。不同模型按擅长任务分工，用户可更正；不要把角色安排写成某品牌永久优于另一品牌。

经理仅在可验收成果、业务疑问、跨组冲突、资源不足、无法继续、目标收窄或范围排除时交短报。主调度复核疑问和关键节点，直接面向用户，日常不重读全部执行日志。

## 先接续，后确认

执行者先保存结果，再通知直属经理。经理核一次必要差异和证据，实际恢复原负责人、指定继任或登记有效排队后，确认该阶段交付。文档整理和完整汇报在接续之后。

同一任务换阶段、机器或负责人时沿原记录继续；独立新目标才另登记。不能把每次转交都记成一个已完成任务。没有执行位时写明负责人、下一步、提供者与恢复条件，条件到位真正启动。

转组先由原经理停止该任务的新派工，核在途工作并保存检查点，继任经理确认接手后更新归属。没有接任授权不得抢另一活跃调度的队列；交接不代表旧代理已经退出。

## 资源统筹只负责统一分配

指定一位现有经理兼任资源统筹。统一查询用户明确登记并允许使用的机器，计入正在运行、已分配尚未启动和已给各组预留的资源。多位经理不能根据同一张空闲快照各自把机器排满。

| 分开判断的约束 | 查询或核对什么 |
| --- | --- |
| 代理名额 | 当前工具实际接纳、经理和巡检的占用，不把配置值当已生效容量 |
| 每机内存与处理能力 | 可用内存、压力、交换区变化、当前重任务与已知同类峰值；未知峰值明确标未知 |
| 磁盘与工具 | 实际工作目录和输出位置、可用空间、任务需要的工具链与运行环境 |
| 写权 | 文件唯一写入者、共享产物归属、隔离构建目录 |
| 桌面焦点 | 哪些步骤需要前台、用户是否占用、隔离能力是否已验证 |

资源统筹给组划当前机器份额与任务预算，业务经理在预算内逐项指定执行机器、目录和前台时段。超预算、重任务或跨组换机先调整分配；执行者不全机探测、不自选机器、不借他人构建目录。

容量释放、候选到位、启动失败或排队积压时重新核负载，实际安排原待办。不要把一次预算固化为每组一个编译或每机固定几个桌面任务；编译、链接、已编测试、轻量读写和前台操作分别看。某项资源满只排受限步骤，其他机器与独立工作继续。

资源统筹确定路线后，传送产物、启动程序和回传证据由原执行者完成，不能把所有具体操作也串到资源经理手里。新增机器先核已有连接方式和任务能力，再纳入已准机器池；不扫描未登记设备，也不自行改认证。

## 集成也按车道并行

大量执行者交付后，单一集成写入者会成为新的积压点。集成经理按实际文件集合分车道，仍然遵守每个文件只有一位写入者：

```text
业务修复车道与各自已核验候选
              ↓
界面集成车道  │  适配层集成车道  │  内核集成车道
各管互斥文件集合，组合本层候选并跑相关检查
              ↓
最终集成车道
合并各层组合 → 生成共享文件 → 构建 → 组合验收
```

这些层名只是示例，单仓也可按模块划分。候选少时一条车道足够，不为并行拆到每文件一人。

- 每条集成车道只写自己的集合。两条都需改同一文件时，集成经理重划写权；工作树隔离不豁免。
- 共享清单、守护登记、依赖锁文件和生成产物只由最终集成车道写或重新生成。子车道可交付已核实的依赖声明和生成输入，由最终车道统一更新；本地构建副产物不作为共享文件改动提交。
- 最终车道汇总各层组合、处理真实交集、统一共享文件并做组合验收，不逐条重做已通过且未受影响的业务验证。
- 同模板批量迁移可依项目批准按类按批抽一至两条独立审查，其余入口仍有直接验证和棘轮检查；含新逻辑、合同或未覆盖风险的改动单独审查。抽样不扩大授权，也不减免原问题的真实验收。
- 按当前组合身份交付，不用早期子分支产物冒称最终版本通过。交集发生变化，只补受影响检查。

这里公开的是组织方法，不附带自动合并、共享文件生成或发布工具；各项目沿用自己的实现。

## 巡检与角色检查

巡检读取同一任务记录和当前代理状态，发现交付未接、经理已停但仍有可执行工作、记录与工具矛盾、已准资源空闲却没人接待办时，先核最新事实再通知直属经理。只能在获得恢复权限且宿主支持时恢复该经理，不能改负责人、代确认或自行派业务。

周期按成本和响应要求选择，原实践用过十分钟。相同事件、相同事实去重，健康时保持安静。经理回应“正在看”后仍需有实际检查点或接续；超过约定响应窗口无动作、投递失败或跨组异常，再报主调度。模型容量失败、代理名额不足、机器失败分别记录，不据其中一种推断其他进程已经退出。

经理每轮结束核本组记录、当次代理状态和漏接检查；巡检看全局，主调度看经理摘要、当次经理状态及异常。检查结果正常不能代替用户目标完成。停止对话后的恢复与活动会话内投递分别验证，不凭技能文本承诺后台唤醒。

## 发布范围

只有发布获授权后才指定发布职责。授权时盘点已有候选与交付，核实际身份、冻结范围；冻结后的新反馈仍处理，归后续版本。用户明确要求加入，或本版自身改动引入回归时，记录最小调整并重新冻结。不能边打包边改冻结树，也不能因新反馈无限拖延已授权版本。

范围、最终包验证、公开回读与测试资源清理由发布负责人追到终点，仍受用户原授权约束。向主调度交“本版带入 / 本版暂放及原因 / 后续版本新增”，不把普通候选交付当作公开发布许可。
