# 止血线与类治理线

用户不应为整类重构等待眼前问题修复，也不应反复遇到同一种根因。两条线分开交付、并行推进，同文件写入和资源冲突只协调相应步骤。

## 先确认治理范围

按当前项目或用户授权推进类治理；技能不能自行把局部修复扩大为全仓重构。已有明确同类治理授权时，经理直接开工，不反复请批。没有时，最小修复照常做，另报真实同模式入口、建议范围和代价。

同一类的多个缺陷复用一条类治理主线，每条原问题保留结果和验收归属。对每个新缺陷都另建一套类目录会产生重复调查和互相冲突的写入。

## 两条线分别负责什么

| 线 | 直接交付 | 不能用什么代替 |
| --- | --- | --- |
| 止血线 | 当前缺陷最小修复、相关测试、原用户动作通过、自建资源收尾 | 类治理方案、库选型或源码候选 |
| 类治理线 | 根因归类、旧入口盘点、试点与分批迁移、已登记的防回退守护 | 一份新模块、试点通过或首批队列清空 |

只修单点的三种情况：纯文案样式布局；数据配置或环境问题；查证确实没有第二处同模式的孤立逻辑错误。记录依据即可，特别是最后一种要写在哪些相关模块查了什么，不凭感觉判孤立。

## 从真实根因分类

分类依据是共享的错误机制，不是相似报错文字。先复用项目已有类目录；新类选一条真实场景试点，证明问题和做法，再按已授权范围铺开。下面七类来自原项目经验，只是起点，不要求别的项目也分成七类：

| 示例类别 | 需要查的共同机制 |
| --- | --- |
| 参数来源 | 默认、继承、现场覆盖和派生值的来源与优先关系是否明确 |
| 实例身份与保留增量 | 模板与实例是否混淆，用户修改在重建或重排后是否归回同一对象 |
| 字段合同 | 字段经过读取、转换、编辑、保存与回读时是否丢失或变型 |
| 查询状态 | 过期响应、写后失效、作用域切换和页面状态由谁管理 |
| 坐标空间 | 不同空间、单位或变换边界是否被混用 |
| 表单描述 | 显示值与存储类型的约定，零、空串、假值和表达式是否保持语义 |
| 现场事实 | 同次动作的事实来源、复用与失效是否明确，丢缓存后是否仍正确 |

经理同时查成熟库或大型项目的做法，见 [mature-libraries.md](mature-libraries.md)。找到候选不等于已获采用许可；止血线不等选型。

## 试点通过即按授权推广

先明确一类的范围、真实输入、完成标准和失败停止条件。试点必须走通代表性用户链；若新抽象不能改善问题，或现有能力已经够用，就记录结论，不为证明方案而扩范围。

已授权推广的类，试点通过即可按独立入口并行，不等其他类试点或另一次开工口令。每批成熟就进入候选，按真实交集补组合检查。复用已绿证据，新增或变化的路径另验。重构需要的直接调用链修改属于原范围；新产品行为仍需决定。

重复模板迁移可按已批准批次规则抽样独立审查，直接验证和守护仍逐入口落实；新逻辑和新合同单独审查。跨车道共享文件交唯一集成写入者，不把所有源代码工作也串行等待它。

## 盘点闭合才知道何时停

范围可以是某目录、某类消费者或已批准全仓范围，先说清是什么。每个旧入口保留一行：

| 入口 | 归类状态 | 依据 | 负责人或重新评估条件 |
| --- | --- | --- | --- |
| 某编辑入口 | 已迁移 | 对应候选与用户链验证 | 当前负责人 |
| 某读取入口 | 现有能力足够 | 已消费同一合同，无第二套规则 | 当前负责人 |
| 某历史导出入口 | 暂不做 | 具体原因和影响范围 | 明确触发条件与承接人 |

“暂不做”须符合原范围约定或获准调整，不可擅自缩小用户目标。未查、待迁、待验、排队和缺程序都仍是未结项。完成条件同时满足才结束本类：

1. 批准范围内的旧入口盘点闭合，每个入口有上述一种状态和实际依据。
2. 本类已登记可运行的轻量棘轮，新代码再走旧路会失败。

首批清单结清和全范围完成分开；结束一批不撤销剩余范围。全部到终点后停止，不为保持代理活跃继续开旁支。

## 棘轮守护的含义

每类一个轻静态扫描，登记到项目已有检查入口，在候选交付时运行。以单个一秒内为目标，记录实际耗时和扫描范围；不编译、不开桌面程序。大型范围超预算时收窄到有效规则或复用已有扫描能力，不能声称已经达标。

存量旧模式使用**具体位置或稳定入口身份的允许集合**冻结，只许删除，不得增加。比较新增身份，而不只比较总数：删一处旧模式再在别处新增一处也必须失败。未迁移的旧模式允许暂存，但没有新增旧模式才可通过。

举例：旧入口甲、乙在基线中，迁掉甲后基线收为乙。新入口丙再使用旧模式，即使总数没超过最初数量，也应变红。不能通过扩大允许集合、忽略目录或把新位置改名成旧位置消除报警；确需调整规则由该类负责人核差异并记录原因，不静默更新基线。

静态规则只能发现它定义的模式，不能证明业务正确或覆盖了所有变体。真实行为仍用本题相关测试与原用户动作验证，不再另造一套昂贵验收系统。

## 汇报分开结算

对原问题报告：已修 / 未修、真实链通过 / 未过 / 未测，以及谁继续。

对类别报告：批准范围、盘点三态数量、仍未结项、守护登记及运行结果。源码、构建、平台、集成、发布和用户验收分别说；已清队列和代理退出不算总完成。
