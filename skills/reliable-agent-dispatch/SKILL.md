# 可靠的多代理调度

让每个已授权的用户结果持续有人负责，同一线程从定位追到最终验收。主调度只对接用户，车道经理只对接执行者，不按业务分组、不逐步核收；单一小任务由当前负责人直接闭环。

本技能执行[第二版协调结构](../../docs/coordination-structure.md)，不附带队列服务、状态脚本或机器工具。使用前核当前宿主能力；本项目的上下文、缓存与成本经验不能直接当成其他环境的结论。

## 开始前确认能力、原记录与授权

读当前项目规范、已有授权、原任务记录和最近交接。发布、云端部署、客户和公开数据写入、永久删除、凭据及权限变化须有明确授权；已有授权持续有效，不重复请批。只读、暂停及用户禁用的机器边界优先。

核实际代码目录、基线、已有改动、执行者状态及运行句柄，保留他人修改。复用原记录、原负责人和证明范围明确的已通过证据；旧台账的“执行中”不证明仍在执行。同一问题的交付只由一位车道经理消费，原调度活跃时先落实交接。

核启动、通知、恢复、列状态、有界等待和持久交付的实际语义，见 [host-adaptation.md](references/host-adaptation.md)。消息送达不等于闲置线程已恢复，配置保存不等于能力生效。

## 协调结构：经理只做协调

| 角色 | 职责 |
| --- | --- |
| 执行者 | 一个独立问题一个，同一线程完成定位、修复、测试、必要构建、真实验收、保存回读、清理和候选登记；自己查获准机器负载、登记占用并等构建 |
| 主调度 | 用户唯一联系人；转达用户原话、反馈、决定和授权，立即呈现待决定问题并写回答复；不派执行者、不接车道、不读执行过程 |
| 车道经理 | 来一个问题开一个执行者；停住或依赖到位时恢复原线程；待决定问题交主调度；需要合入或发布就拉起相应执行者；只核一行结论和最终证据是否齐备，不逐步核收 |
| 公共设施 | 机器分配用现成脚本，不设常驻资源代理；集成、发版各由一个执行者做到终点；独立审查用于高风险改动；界面由适合且获准的模型按需协作 |
| 巡检 | 低成本查漏接、依赖到了是否有人叫醒、责任是否挂在不活动经理名下，发现后报主调度；不派业务、不规划 |

多个独立问题在授权及工具能力内并行，不按业务凑组，不按固定未结数量设经理容量。确实接不过来才增加协调者；原经理退出或挂起时，当轮转交未结责任，执行者继续原线程。各角色共用实际代理名额，机器容量另查，详见 [manager-hierarchy.md](references/manager-hierarchy.md)。

## 一个问题一个线程，从定位做到验收

首次派单写清**用户目标与直接证据、负责范围、禁止事项、最终验收标准**，补实际目录、基线、机器边界和现成验证入口。验收覆盖本题必要的真实入口、保存后新进程回读、自建资源清理和最终回执，不拆成阶段派单，见 [templates.md](references/templates.md)。

执行者到下一阶段直接继续，等机器或构建时保留句柄并用宿主支持的等待。只在需要用户决定、需要别人的产物或冲突裁决、做完时交付；结果、证据和剩余项一次说清。

继续做就用实际恢复工具启动原线程。阶段结束、上下文变长、发生压缩或暂时等待都不是换人的理由；只有工具证实原线程无法恢复才登记继任。先核在途进程，继任只读最后最小回执和开工必需的源码与边界，不重读全部历史。

必要的界面岗位协作和高风险审查保留，原执行者仍负端到端责任。普通改动由实现者自审加直接相关测试；权限、删除覆盖、报价或生产输出、不可逆迁移、云端部署及发版等高风险按项目规范由非实现者审查，不给每个候选另配审查线程。

## 反馈只用四个状态

| 状态 | 必填内容 | 离开条件 |
| --- | --- | --- |
| 处理中 | 一句人话标题、实际执行者；收到后 15 分钟仍无人负责须提示异常 | 需要用户决定、候选修好或结案 |
| 等你定 | 问题、推荐、推荐怎么做、不选推荐的代价，以及实际呈现记录 | 用户答复；普通决定呈现后 3 分钟无回复按推荐 |
| 待发版 | 候选身份、提交和验证层级 | 获准发布并公开回读通过 |
| 已完成 | 已发版修复并写版本 / 不是缺陷已答复 / 不做 / 并入原问题 | 新证据到位或用户改主意时重开 |

没有“排队”和“等外部”状态。等机器、等构建仍是处理中，依赖、提供者和恢复条件写在同一记录里。

缺证据先找本地原件，仍缺就把缺什么、向谁要、查过哪里及可直接发送的请求文案记入证据请求库。用现有材料完成可做部分并注明“原案未覆盖”；证据到位重开原问题补验，不据猜测写数据。

待决定事项出现后，主调度立即实际呈现，不攒着。**普通决定呈现后 3 分钟未回复，记“未答复，按推荐”并执行；发布、云端部署、客户和公开数据写入、永久删除、凭据及权限变化不适用，缺明确授权始终不得自动放行。** 用户事后推翻普通推荐时照新决定执行；未呈现不能起算。

超时约定须由用户或项目明确采用，且遵守宿主更高优先级的交互规则；沉默不能扩大权限。用已有状态工具校验必填字段、生成同一张进度表，在处理状态或被唤醒时检查超时，不为计时新建常驻服务。

## 同一文件可以多线并改

各线使用独立工作树、分支和独占构建目录，全程复用本线输出。默认乐观合并：先合者先进，后合者在最新基线上变基；解冲突保留已合入的内容，不整块采用自己一边。

不做无关整文件格式化、大段搬动和批量重命名。确实不能并改的少数热点和共享现场单独登记，例外清单默认空；个别生成产物串行更新不等于所有文件单写。

## 业务判断由处理问题的执行者完成

明确缺陷按已有授权最小修复；新功能、行为变化或产品取舍先核真实问题、已有入口、用户成本与影响，带推荐交主调度，按已采用的普通决定约定处理。技术安排依据已有规范直接定；未授权旁支只报告，不实施、不阻塞。

修完先记根因类别、同模式入口及守护是否漏掉，不为每条缺陷自动另开类治理。按项目约定复盘提议，用户批准某类后才开一个执行者做该类治理，不阻塞原问题；终点和轻量守护见 [bug-by-class.md](references/bug-by-class.md)。

执行者主动检索成熟库、官方做法和行业通用解法，说明替代范围、维护、许可和兼容成本，交主调度向用户提议，当前修复不等选型。库与算法按真实链验证；**工作方法先列前提、对照实际，在小批车道试跑一两天，端到端数字改善才推广，变差撤回。** 见 [mature-libraries.md](references/mature-libraries.md)。

## 接续和沟通保持轻量

车道经理使用能被交付唤醒的长超时等待，不短轮询、不重读执行过程、不另开进度探子。给主调度的消息限待用户决定、关键路径卡住超过 15 分钟和每日晚报；宿主或用户要求的响应节奏仍须遵守，普通进度不逐层转发。

关键路径卡住超过 15 分钟，修好工具重试、换获准机器或路径，或经主调度马上问用户，不能干等。命令错误或工具调用失败不自动算外部欠账。

执行者先保存最终或阻塞回执再通知；经理落实恢复原线程、接上依赖或转交责任后再确认，不用“收到”代替动作。沟通见 [communication.md](references/communication.md)。

每天看每个问题用了几个线程、中途来回几次、管理类 token 占比。原实践目标为 1–2 个线程、不超过 3 次、约 30%；换环境先立基线，不承诺普适效果。

## 集成、发布与结果验收

集成、发版各由一个执行者追到终点，复用已通过且未受影响的证据，只补组合差异。发布须有授权；核当时已有候选与交付并冻结范围，之后新增归后续版本，用户明确加项或本版回归才调整并重新冻结，不能边打包边改冻结树。

核候选源码、实际程序、真实输入和产物属于同一交付。源码、构建、平台真实操作、集成、发布和用户验收分别说；保存相关问题用新进程重新打开回读，自造场景不冒充原案。

自建资源按已有授权清理，停止自有进程并恢复现场，不清他人资产；仍有人用的移交最后使用者。必要验收失败交原执行者最小追查，达到原用户终点就停止无关扩展和重复审查。

结束前轻量核当前记录、实际代理状态、未接交付和失去协调者的问题，接上可执行的授权余项；状态表正常不等于用户目标完成。没有验证后台唤醒，不承诺离线续跑，不擅加定时器或服务。
