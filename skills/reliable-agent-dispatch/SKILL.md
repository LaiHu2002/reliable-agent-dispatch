# 可靠的多代理调度

目标是让每个已授权的用户问题持续有人负责，直到满足约定结果或遇到明确的外部缺口。用户只对接主调度，补充一次的信息由主调度同步给相关负责人。

## 开始前确认实际能力

先读当前项目规范、用户授权及已有任务记录。用户明确要求只读、暂停、保留某台机器或禁止某类写入时，以该限制为准。进度追问不撤销原来的执行目标；纯状态查询不新增任务。

从本轮实际工具说明确认下表，不猜工具名称、参数、默认并发或唤醒能力：

| 能力 | 本轮需要确认 |
| --- | --- |
| 代理 | 能否启动、列出状态、通知正在工作的代理、恢复闲置代理 |
| 持久记录 | 现有任务表或交付队列的位置、谁写登记、谁写交付、谁确认 |
| 执行环境 | 获准机器、工作目录、共享写入及桌面操作边界 |
| 通知和恢复 | 交付如何抵达主调度，主调度停止后能否恢复，有无直接验证 |

若缺少某项能力，只调整依赖它的步骤。不得用文档记录冒充实际执行，或宣称没有验证的后台保证。具体适配方法见 [host-adaptation.md](references/host-adaptation.md)。

## 接手现有工作

1. 先简短回应用户，再读取已有任务表、交接和未消费交付。
2. 核实际代码目录、分支、未提交改动；核代理状态和已有执行句柄。旧台账写“执行中”不能证明还在运行。
3. 确认本批只有一个主调度消费交付。原调度仍在运行时，先协调消费职责，避免重复派单或同时操作共享现场。
4. 复用已通过且身份明确的证据。同一个用户问题优先交回原负责人；明确无法继续时，再交给具体继任者。

## 按依赖和写权拆任务

单一局部问题直接处理。存在互不依赖的已授权问题且实际工具允许时，并行推进；不要为了并行制造新目标。

每条任务最少写清：用户可见目标、直接证据、负责人、工作目录与基线、文件或模块写权、禁止事项、完成标准、验证入口。使用 [派单模板](references/templates.md)。

- 同一文件同时只有一个写入负责人。独立工作树不授权两个执行者同时改同一文件。
- 有写入冲突时，由主调度裁决交集；无冲突的读取、定位和验证继续。
- 原负责人对同题的定位、最小修复、必要构建、相关实际操作和自建资源收尾持续负责。
- 新发现的独立目标按现有授权判断；未获授权的旁支只报告，不实施，也不阻塞当前问题。

## 单独分配执行资源

分别核算代理名额、每台机器的实际容量、共享文件写权及桌面焦点。代理数量不等于机器任务数量；不同机器的内存不能相加供一个进程使用。

新增编译、链接、桌面程序或计时任务前，由主调度取得获准机器的当前资源信息，计入已派出尚未启动的工作，逐项指定机器和目录。执行者只执行分配；失败后报告现象并继续不依赖故障步骤的工作，由主调度改派。

只串行真正冲突的步骤。桌面焦点被占用，不自动暂停同机无头任务或其他机器。容量取决于本机负载和已验证的隔离能力，不把历史并发数字写成通用上限。

## 启动与接续必须实际发生

调用本轮实际可用的启动或恢复工具，拿到可核对的回执后，才能报告“已派出”或“已接续”。给闲置执行者发普通消息不一定会启动它，必须核实际工具语义。

执行者交付时先保存结果，再通知主调度。交付至少包括：任务身份、完成的阶段、修改及产物身份、验证证据、剩余工作、具体下一步和清理情况。不要只写“完成”。

## 先落实接续，再确认交付

主调度收到交付后：

1. 直接核对本次差异及相关证据，确认没有超出范围。普通候选默认一轮直接审查；本轮引入的阻塞问题才触发必要补查。
2. 分别记录源码、构建、所需平台实际操作、集成、发布和用户验收。只要求与本题结果相关的层级。
3. 若仍有可执行工作，实际续派给原负责人或明确继任者；执行位满时登记具体排队任务和接续条件。
4. 真缺外部条件时，写清缺什么、谁提供、是否已提出请求、影响哪一步、到位后由谁继续。技术方案和机器分配由主调度解决。
5. 只有下一步已经启动、明确排队，或外部等待已交代清楚后，才确认该交付事件已消费。确认交付不等于整个任务完成。

有持久队列时复用其机制；没有时使用现有任务记录，不为普通小任务搭建新调度服务。

## 验收用户结果

检查实际源码、运行程序、输入和输出是否属于本次候选。测试通过、窗口打开或进程存活各自只能证明对应阶段。

需要验证保存效果时，按任务要求保存后用新进程重新打开并读取关键结果。自造场景用于机制探索；没有覆盖原始输入时不能写成原案通过。目标平台不可达时如实记录，继续其他可执行步骤。

源码候选形成后停止无关扩展和重复审查；本题已授权且必要的真实操作仍要继续。集成、发布、外部写入及删除等动作沿用当前用户授权，技能本身不授予这些权限。

## 每次准备结束前

- 对照现有任务记录和本轮实际代理状态，消费新交付，处理工具已结束但台账仍写运行中的项目。
- 有明确可执行余项且执行位可用时，落实接续；已通过的阶段不重复验证。
- 自建测试资源、私有登录副本及自有进程按原定责任收尾，只清理确属本任务且已获准处置的资源。
- 先说用户能看到的结果，再按“问题 / 当前结果 / 还差什么”报告。内部身份放证据中。
- 没有经过验证的后台唤醒能力时，留下具体检查点，明确何时、由谁恢复；不得承诺关闭对话后仍会自动推进。

完成条件是用户目标满足且必要工作已经结束。预算耗尽、交付被确认、代理退出或等待外部输入，都不能单独写成目标完成。
